## 补充发现

1. **R03 的同类问题也在错题练习页**：`ErrorBank.tsx` 在提交时就记分并移出错题本，要到点"下一个"才推进轮次；跟读阶段同理。
2. **R05 的同类问题**：同步进行中 store 又发生变化时，3 秒后的定时同步遇到 `inFlight` 直接返回，之后不会再补。
3. **设计问题（需产品决定，非 bug）**：混合练习的选择题答对也计入 `correctCount`，3 次选择题即可"掌握"一个词，完全绕过拼写和跟读。

## 修复方案与批次

### 第一批：同步一致性（R02 → R05 → R01 → R18）

- **R02**：`errorBank` 数组保留（兼容旧客户端和备份），新增 `errorBankAt: Record<wordId, number>`，记录每个词最近一次进出错题本的时间：正数为加入时间，负数为移出时间。合并时每个词取时间较新的事件；没有时间记录的旧数据按"加入时间为 0"处理；移出标记 60 天后清理。`errorSession` 改为只取本地，不再从云端回填。同步测试中的并集断言相应改写。
- **R05**：确认上传成功后才写 `lastSynced`；失败时按 10 秒、30 秒、2 分钟……退避重试；同步进行中又有新请求时记 pending，跑完再补一次；在同步面板显示最近一次失败。
- **R01**：迁移 `0004` 给 `profiles` 表加 `version` 列。`GET` 返回版本；`PUT` 带 `baseVersion`，用 `UPDATE … WHERE version = ?` 条件写入，版本不符时返回 409。客户端收到 409 后重新拉取、合并、重试，最多 3 次。过渡期内不带 `baseVersion` 的旧客户端照常写入。
- **R18**：新增 `dailyGoalSetAt`，合并时取较新的一方；从未设置过的默认值让给远端。

### 第二批：学习流程与录音（R03、R04、R07、R08）

- **R03**：复用已有的 `currentSession.results[wordId]` 作为幂等标记：已经记过拼写结果就不再调用 `updateProgress`，重新进入时据此恢复阶段和对错。错题轮次增加同样作用的 `answered` 记录。
- **R04**：麦克风流一就绪就接入采集节点并缓存 PCM，再签名、建立连接；`finish()` 遇到尚未打开的 WebSocket，等待打开（带超时）、发送缓存后再发结束帧。
- **R07**：录音服务加代次计数，授权返回时代次已失效就立即停止音轨；界面增加"启动中"状态并禁用按钮；组件卸载后不再启动评分。
- **R08**：把会话号传进 `playAudio`，计算完哈希后重新检查；`finally` 只清理属于自己的取消句柄。

### 第三批：题目与词库（R21、R09、R20、R10、R14）

- **R21**：把修正写进 `scripts/ipa-overrides.json`，防止重新生成时被还原；`validate-words` 增加上述启发式警告，被标出的条目对照 Cambridge 人工确认。音频按文本生成，不受影响。
- **R09**：英 → 中题排除展示拼写相同的干扰项；听音选词题排除音标相同的干扰项（R21 修完后，音标相同的就正好是真正的同音词）。
- **R20**：给 `ear` 加 `forms: ["ears"]`（匹配时先试 forms，例句和音频都不用改）；校验脚本对"匹配到的后缀不像屈折变化"报警告。
- **R10**：建轮次前先过滤未知 ID 并清理错题本；找不到当前词时显示带返回按钮的空状态。
- **R14**：每个难度桶中已掌握的词直接计入已知数，剩余词再按样本正确率估算。

### 第四批：小修（R12、R19、R11、R17、R13）

- **R12**：已获得 = 推导结果 ∪ `achievementsSeen`；连续天数类徽章改用历史最长 streak。
- **R19**：分母为 0 时显示 `—`。
- **R11**：记录加载错误并提供重试；监听 `vite:preloadError` 自动刷新。
- **R17**：校验 `currentSession`、`errorSession` 等嵌套结构，不合格置为 null；导入整体加 try/catch。
- **R13**：`recordSpeak` 写入 `lastSpeakAt`，周报按它筛选；标签改为"本周跟读（每词最近一次）"。

### 暂缓或只改文档

- **R06**：修正 SPEC 中"无损合并"的措辞。
- **R15**：按用户名只统计失败次数，并加"用户名 + IP"维度的计数。
- **R16**：先给哈希加版本前缀，测出当前套餐可承受的迭代次数，再在登录成功时逐步升级旧哈希。
